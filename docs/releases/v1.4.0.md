## DSCodex v1.4.0 — Lighter History

一段看过很多截图的会话，请求体会越过 DeepSeek 网关约 47 MB 的上限，之后每一轮都只收到 HTML `413 Request Entity Too Large`。这一版在请求超过 44 MB 时把老图改小，会话不再卡死；另修好了一类工具调用重放失败。

## Highlights

- **🖼️ 超限旧图自动缩小，不再 413 卡死。** 出站请求超过 44 MB 时，最新 4 张原样保留，更老的图转成有损 WebP（长边 1024、质量 75）；缩完仍放不下，才把最老的图换成一条写明序号、类型、大小的 `input_text` 记录。作者实测一段 44 张图的会话：图片 47.92 → 10.1 MB，整个请求 50.67 → 12.88 MB，44 张全在。转码结果按内容哈希缓存在 `~/.codex/dscodex/image-cache/`。编码器（`sharp`）是找到就用，不是依赖：包仍只声明 `ws`，没装编码器时退回文字记录。想要缩图，运行 `npm install --prefix ~/.codex/dscodex/encoders sharp`。五个旋钮（`max_upstream_bytes`、`keep_recent_images`、`image_max_side`、`webp_quality`、`webp_encoder_dir`）写进 `~/.codex/dscodex/config.json`，`max_upstream_bytes: 0` 关闭。感谢 @Yilmhi（#28）。
- **🔧 tool_search 与函数调用混在同一轮时不再被 DeepSeek 拒绝。** 同一个 reasoning 回合里同时有 `function_call` 和 `tool_search_call` 时，重放顺序现在会被正确修复，不再因此卡住会话。感谢 @LukasAI（#26）。
- **🧪 CI 增加语法检查，仓库增加 PR 模板。** 对 `src/*.mjs` 与 `scripts/*.mjs` 逐个 `node --check`；`.github/PULL_REQUEST_TEMPLATE.md` 列出提交前的核对项（来自 #27 的建议）。
